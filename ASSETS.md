# Art assets

Every visual in the game is looked up by a **logical key** through `js/art.js`, which reads `assets/manifest.json`.
Swapping art needs only manifest and file changes, no code changes.

## What is live now

- **Active art: style A 16-bit pixel pack by Ælfstan** in `assets/pack-styleA/` (`1x/`, `2x/`, `3x/` folders, plus the pack's own `README.md`, full sprite `manifest.json` and `builder-manifest.styleA.json`).
  The pack's `native/`, `sheets/` and `tools/` (sources) are not shipped; they stay with Ælfstan's zip.
- `assets/manifest.json` (active) is generated by `node tools/build-manifest-styleA.mjs` from the pack's drop-in manifest. It keeps only the game's keys and adds:
  - `hc`: the high-contrast twin (`<name>_hc.png`) of an entry. **Settings → High contrast** (saved in `localStorage` as `diceGame.settings`) switches to these and to `bg_hc_tile`.
  - `kind: "button"` with `states.pressed` / `states.disabled` for `ui_btn_*`. These pixel buttons have their label baked in, so the game shows them as the button face with a small caption (price, counts) underneath; the full text is the accessible name.
- `assets/manifest.placeholder.json` is the **fallback**: `"fallback"` in the active manifest points at it. If a key is missing from the active manifest or its file fails to load, the placeholder SVG is used, then a CSS-drawn die.
- `"pixelated": true` → sprites render with `image-rendering: pixelated`. Sprites are shown at whole-number multiples of their 1x size only (dice 64 CSS px on phones, 128 on desktop; buttons 128×48).

## Naming convention for the art pack

- Dice faces: `die_<shape>_face<value>`, e.g. `die_d6_face3`, `die_d20_face17`, `die_coin_face10`.
  One body per shape; special dice are shown with an **icon badge** over the normal face (the brief's "draw once, overlay" advice), so there are no per-special face sprites.
  d6 placeholders use pips for 1–6 and numerals above 6 (the Overcharged die rolls 4–9 on a d6 body).
- Special-die icons and HUD icons: `icon_<name>`, e.g. `icon_mult_x2`, `icon_coin`.
- UI: `ui_<name>`, e.g. `ui_btn_roll`, `ui_logo`. Buttons always show their text label too, so a button icon is optional.
- Colour layers (from the research brief): blue = points, red = multiplier, gold = money, purple = rule-bending, grey = disabled.
- Formats: PNG (or SVG/WebP). For pixel art set `"pixelated": true` in the manifest (adds `image-rendering: pixelated`).

### Resolutions (1x / 2x / 3x)

Two layouts are supported; pick one for the pack.

1. **Suffixes** (default): `die_d6_face3.png`, `die_d6_face3@2x.png`, `die_d6_face3@3x.png` side by side.
2. **Folders**: `1x/die_d6_face3.png`, `2x/die_d6_face3.png`, `3x/die_d6_face3.png`.

The browser picks the right file via `srcset` (`1x, 2x, 3x`).

## Manifest format (`assets/manifest.json`)

```jsonc
{
  "base": "assets/",           // all paths are relative to this
  "pixelated": false,
  "preferPack": false,         // true: try `pack` first, then the per-key entry
  "pack": null,                // or { "dir": "pack/", "ext": ".png", "scales": [1,2,3], "layout": "suffix" | "folders" }
  "assets": {
    "die_d6_face3": { "src": "placeholder/die_d6_face3.svg" },                        // single file
    "icon_mult_x2": { "src": "pack/icon_mult_x2.png", "scales": [1, 2, 3] },          // -> @2x/@3x siblings
    "ui_btn_roll":  { "src": "pack/1x/ui_btn_roll.png",
                      "srcset": { "2x": "pack/2x/ui_btn_roll.png", "3x": "pack/3x/ui_btn_roll.png" } }
  }
}
```

**Dropping in the whole pack in one step:** copy the files to `assets/pack/` and set
`"pack": { "dir": "pack/", "ext": ".png", "scales": [1,2,3], "layout": "suffix" }, "preferPack": true`.
Any key the pack is missing falls back to the placeholder entry, then to a CSS-drawn die, so a partial pack never breaks the game.
Fallback order for each key: pack (if `preferPack`) → `assets[key]` → pack (if not `preferPack`) → CSS-drawn fallback.

Placeholders are generated by `node tools/gen-placeholders.mjs` (it rewrites `assets/placeholder/` and the manifest).
`node tests/sim.mjs` checks that the manifest covers every key below, that each file exists, and that this list is complete.

## Pick 5 of 7 (layout 3): no new art

The hand shows the 7 drawn dice before the roll using existing keys only: `die_<shape>_blank` for the body,
the special's badge icon (its `icon` key from `js/specials.js`), and a CSS text tag with the shape or special name. Selection is pure CSS:
picked dice lift 6px with a gold ring and a CSS tick (`.die.pick.picked`, `.pickmark`); the unpicked dice after
the roll are the same blank sprite dimmed with `opacity` + `grayscale` (`.die.benched`). If a pack later wants a
dedicated selection frame, add a `ui_select_ring` key to the manifest and swap it in `pickBtn` in
`js/ui/roundView.js`.

## Binary counters (style A pack, counters section)

Counters (`bin4`, `bin8` shapes) are one die slot: a 32×32 native sprite (64 CSS px at 1x, 128 on the desktop table).
`main.js` exposes each counter key as a `--art-<key>` CSS custom property; `css/style.css` uses them as backgrounds
(`background-size: 100% 100%`, `image-rendering: pixelated`). Each bit is a 4×7 seven-segment cell placed at the body
entry's `bit_cells` (native top-left corners, MSB first; 8-bit = MSB nibble on the top row), which
`tools/build-manifest-styleA.mjs` copies from `assets/pack-styleA/manifest.json`. If a key has no art, the CSS look under
each `var()` is the fallback. These keys are listed by `counterArtKeys()` in `js/art.js`; they ship in the active
manifest but stay out of `requiredKeys()` (the placeholder manifest does not cover them).

| Key | Pack sprite | What |
|---|---|---|
| `die_bin4_body`, `die_bin8_body` | `counter_<n>bit_body` | housing + empty screen (bits drawn on top) |
| `die_bin4_blank`, `die_bin8_blank` | `counter_<n>bit_blank` | unrolled (hand, bench, shop) |
| `led_bit_on`, `led_bit_off` | `counter_bit_1`, `counter_bit_0` | 4×7 cell: lit 1 / lit 0 |
| `counter_bit_tumble_1`, `counter_bit_tumble_2` | same | per-cell flicker while the counter rolls |
| `icon_counter4`, `icon_counter8` | `special_counter_<n>bit_icon` | badge on plain counters |
| `icon_link` | `special_chain_icon` | Link icon (info / bag lists) |
| `overlay_chain` | `special_chain_overlay` | 42×42 Link overlay (counter at 2,8): violet ring, left half-link stub, badge |
| `fx_chain_link`, `fx_chain_link_lit` | same | 16×8 connector on the lower bezels between linked neighbours (lit when the chain fires) |
| `counter_readout` | same | 34×14 decimal tag ('=' baked in, up to 4 digits) at counter x − 1, y − 12; one tag centred over a chain |
| `fx_link_glow_1`, `fx_link_glow_2`, `fx_link_glow_3` | `fx_chain_glow_1..3` | glow pulse on linked counters, 1-2-3-2 at ~10 fps (no `_hc` twin in the pack) |

The pack's bracket pieces (`fx_chain_bracket_*`) are not used: the chain animation is overlay + connector + glow + one readout.

## Modifiers on every shape (style A art shipped)

The nine modifiers (Ruby, Ember, Last Call, Matching, Overcharged, Gold, Twin, Echo, Glass) can sit on any d4–d20.
Ælfstan's style A pack delivers all 78 keys below with `_hc` twins (synced by `tools/sync-pack-styleA.mjs`, which now ships
`modArtKeys()` + `modRingKeys()`). Overcharged uses `mod_overcharged_<shape>` (badge "+3") on every shape, d6 included;
the old d6-only `special_overcharged_*` sprites ("4-9") are not used for modifier dice.
`modArt()` in `js/ui/dieView.js` tries, per die, first hit wins:

1. `mod_<mod>_<shape>`: per-shape overlay, **42×42 native** (84×84 CSS at 1x), the 32×32 die drawn at (2,8), the same canvas as
   `special_*_overlay` / `fx_ring_*`: a layer-coloured ring traced to that shape plus the badge top-right. It is drawn over the
   plain face sprite, so faces are not redrawn per modifier.
2. `mod_badge_<mod>`: generic badge, **28×11 native** (56×22 CSS), top-left at die origin + (11, −8), any shape, like `special_*_badge`.
3. The special's `icon` key as the corner badge (only if neither sprite exists).

**Pointed tops (d4, d8, d10, d20): badge nudged up 2 native px** (`MOD_BADGE_NUDGE` in `js/art.js`) so the apex and its ring show.
The per-shape sprite has the badge baked in at (13,0) with the ring erased under it, so for these shapes `modArt()` draws
three layers: `mod_<mod>_<shape>` clipped out of the badge zone (x ≥ 12 + pill_x, y < 12), `fx_ring_<shape>_<layer>` for
rows 10–11 of that zone (row 9 stays the 1px gap), and `mod_badge_<mod>` at (13,−2). Outside the badge zone
`mod_<mod>_<shape>` and `fx_ring_<shape>_<layer>` are pixel-identical in the pack (normal and hc), so this is the same art with
the badge 2px higher. `pill_x` (left edge of the right-aligned pill: ruby 0; ember, last call, matching, overcharged, glass 6;
gold, twin, echo 15) is measured from the PNG by `tools/build-manifest-styleA.mjs`. Flat tops (d6, d12) use the sprite as drawn.
`tools/mod-art-check.mjs` + `tools/mod-art-check.py` render every modifier on every shape in the browser (normal + hc) and
compare them pixel by pixel with the pack's native layers composed this way.

Layout: the badge sits 10 native px above the die (40px at the desktop table's 2x). The wide round layout reserves that
(table padding 90px, two-column breakdown, 20px side padding on the dice row) and drops table dice to 3x (96px) at
760–799px tall so everything fits; shop offer dice get 12px top / 14px right margin.

Each key also wants an `_hc` twin. They are listed by `modArtKeys()` in `js/art.js` (kept out of `requiredKeys()`, so missing art is fine).
`<mod>` ∈ `ruby, ember, lastcall, matching, overcharged, gold, twin, echo, glass`; `<shape>` ∈ `d4, d6, d8, d10, d12, d20`.

| Keys | Count | Notes |
|---|---|---|
| `mod_<mod>_<shape>` | 54 (+54 `_hc`) | e.g. `mod_glass_d20`, `mod_gold_d4`. Badge text should not be shape-specific (Overcharged "+3", not "4-9"; Gold "$" or "$+"). |
| `mod_badge_<mod>` | 9 (+9 `_hc`) | shape-free badge; the pack's `special_<name>_badge` works except Overcharged ("4-9") and Last Call (id `lastcall`) naming |
| `die_d4_face5`…`die_d4_face7`, `die_d8_face9`…`die_d8_face11`, `die_d10_face11`…`die_d10_face13`, `die_d12_face13`…`die_d12_face15`, `die_d20_face21`…`die_d20_face23` | 15 (+15 `_hc`) | Overcharged faces above each shape's top face, 32×32 native, numerals like `die_d6_face7`–`face9`.
