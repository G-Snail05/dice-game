# Art assets

Every visual in the game is looked up by a **logical key** through `js/art.js`, which reads `assets/manifest.json`.
Swapping art needs only manifest and file changes, no code changes.

## What is live now

- **Active art: style A 16-bit pixel pack by Ælfstan** in `assets/pack-styleA/` (`1x/`, `2x/`, `3x/` folders, plus the pack's own `README.md`, full sprite `manifest.json` and `builder-manifest.styleA.json`).
  The pack's `native/`, `sheets/` and `tools/` (sources) are not shipped; they stay with Ælfstan's zip.
- `assets/manifest.json` (active) is generated by `node tools/build-manifest-styleA.mjs` from the pack's drop-in manifest. It keeps only the game's keys and adds:
  - `hc`: the high-contrast twin (`<name>_hc.png`) of an entry. **Settings → High contrast** (saved in `localStorage` as `diceGame.settings`) switches to these and to `bg_hc_tile`.
  - `kind: "button"` with `states.pressed` / `states.disabled` for `ui_btn_*`. These pixel buttons have their label baked in, so the game shows them as the button face with a small caption (price, counts) underneath; the full text is the accessible name.
- `assets/manifest.placeholder.json` is the **fallback**: `"fallback"` in the active manifest points at it. If a key is missing from the active manifest or its file fails to load, the placeholder SVG is used, then a CSS-drawn die.
- `"pixelated": true` → sprites render with `image-rendering: pixelated`. Sprites are shown at whole-number multiples of their 1x size only (dice 64 CSS px on phones, 128 on desktop; buttons 128×48).

## Naming convention for the art pack

- Dice faces: `die_<shape>_face<value>`, e.g. `die_d6_face3`, `die_d20_face17`, `die_coin_face10`.
  One body per shape; special dice are shown with an **icon badge** over the normal face (the brief's "draw once, overlay" advice), so there are no per-special face sprites.
  d6 placeholders use pips for 1–6 and numerals above 6 (the Overcharged die rolls 4–9 on a d6 body).
- Special-die icons and HUD icons: `icon_<name>`, e.g. `icon_mult_x2`, `icon_coin`.
- UI: `ui_<name>`, e.g. `ui_btn_roll`, `ui_logo`. Buttons always show their text label too, so a button icon is optional.
- Colour layers (from the research brief): blue = points, red = multiplier, gold = money, purple = rule-bending, grey = disabled.
- Formats: PNG (or SVG/WebP). For pixel art set `"pixelated": true` in the manifest (adds `image-rendering: pixelated`).

### Resolutions (1x / 2x / 3x)

Two layouts are supported; pick one for the pack.

1. **Suffixes** (default): `die_d6_face3.png`, `die_d6_face3@2x.png`, `die_d6_face3@3x.png` side by side.
2. **Folders**: `1x/die_d6_face3.png`, `2x/die_d6_face3.png`, `3x/die_d6_face3.png`.

The browser picks the right file via `srcset` (`1x, 2x, 3x`).

## Manifest format (`assets/manifest.json`)

```jsonc
{
  "base": "assets/",           // all paths are relative to this
  "pixelated": false,
  "preferPack": false,         // true: try `pack` first, then the per-key entry
  "pack": null,                // or { "dir": "pack/", "ext": ".png", "scales": [1,2,3], "layout": "suffix" | "folders" }
  "assets": {
    "die_d6_face3": { "src": "placeholder/die_d6_face3.svg" },                        // single file
    "icon_mult_x2": { "src": "pack/icon_mult_x2.png", "scales": [1, 2, 3] },          // -> @2x/@3x siblings
    "ui_btn_roll":  { "src": "pack/1x/ui_btn_roll.png",
                      "srcset": { "2x": "pack/2x/ui_btn_roll.png", "3x": "pack/3x/ui_btn_roll.png" } }
  }
}
```

**Dropping in the whole pack in one step:** copy the files to `assets/pack/` and set
`"pack": { "dir": "pack/", "ext": ".png", "scales": [1,2,3], "layout": "suffix" }, "preferPack": true`.
Any key the pack is missing falls back to the placeholder entry, then to a CSS-drawn die, so a partial pack never breaks the game.
Fallback order for each key: pack (if `preferPack`) → `assets[key]` → pack (if not `preferPack`) → CSS-drawn fallback.

Placeholders are generated by `node tools/gen-placeholders.mjs` (it rewrites `assets/placeholder/` and the manifest).
`node tests/sim.mjs` checks that the manifest covers every key below, that each file exists, and that this list is complete.
